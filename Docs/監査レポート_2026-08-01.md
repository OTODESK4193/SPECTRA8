## 2. 全ノブのスムージング検証

### 2-1. スムージング済み（問題なし）
| パラメータ | 方式 | 場所 |
|---|---|---|
| MIX / OUT LEVEL | `LinearSmoothedValue` 20ms・**サンプル毎** | PluginProcessor.cpp:1005-1006 |
| FMT SHIFT / FMT STRETCH | 1極 τ≈5ms @16k | PluginProcessor.cpp:812-814 |
| DETUNE / NOISE | 1極 τ≈5ms @16k | ExcitationEngine.cpp:379-381 |
| LPC の k（反射係数）| 制御ブロック内サンプル毎ランプ | LpcVocoder.cpp:472-473 |
| LPC の G（ゲイン）| att5ms / rel30ms 非対称 | LpcVocoder.cpp:446-447 |

### 2-2. 未スムージング（2ms の階段状 = ジッパーノイズ源）
制御レート 32サンプル@16k = **2ms 毎に値がジャンプ**します。

- **RESONANCE** — 毎サンプル `computeFilterCoeffs()` に生値が入る。フィルタ係数が2ms毎に跳ぶ。
  RESONANCE を手で回すと「ジリジリ」が乗る最大の原因。
- **CHARACTER** — Filterbank ではエンベロープ時定数、LPC では γ（極半径）へ直結。
  γ が跳ぶと LPC の極が跳ぶのでプチッと鳴る。
- **BASE PITCH / M.PITCH / PITCH Q / TRACKING** — オシレータ周波数へ直結。
  特に **M.PITCH を LFO で変調すると 2ms 刻みの階段ピッチ**になる。
- **NOISE COLOR** — ノイズBPFの fc が跳ぶ。
- **LOFI / WT POS / PULSE WIDTH / BEND / SYNC / VOCODE** — 同上。

### 2-3. さらに粗い（ホストブロック毎 = 最大 40ms 以上の階段）
- **FX 全パラメータ**（`fx*Amount`, `res*`, `drv*`, `gate*`, `cho*`, `rev*`）
  → `PluginProcessor.cpp:934-990` でブロック先頭に1回読むだけ。FxChain 内部にも
  スムージングは無い（`FxChain.h:836-857` `syncParameters`）。
  バッファ 1024smp なら 21ms 刻み。Reverb Size や Res Root を動かすとハッキリ段差が出ます。
- **BANDS EQ の各帯域ゲイン** — `mBandGains[i].load()` を毎サンプル生読み。EQ をドラッグ中はジッパー。
- **LIMIT ボタン** — ON/OFF が瞬時切替。クロスフェード無し → クリック。

### 2-4. 「必ずクリックが出る」もの
- **BANDS ノブ** — `FilterbankVocoder.cpp:61` `rebuildLayout()` の最後で `reset()` を呼び、
  全フィルタ状態をゼロクリアしている。バンド数が1つ変わるだけで**必ずプツッと鳴ります**。
  （ModMatrix が BANDS を変調先から外しているのはこのためですが、手で回しても同じです）
  → 対策: バンド数変更時は旧レイアウトと新レイアウトを 20〜30ms クロスフェードする。

### 推奨の一括対策
`ModMatrix::Dst` の全宛先ぶんの 1極スムーザ配列を `PluginProcessor` に持たせ、
`moddedParam()` の戻り値をそこに通すだけで 2-2 は全て解決します（τ=5ms 程度）。
実装量は小さく、既存の `mFmtShiftSm` と同じ書き方で統一できます。

## 3. Filterbank / LPC のレベル適正化【最重要】

数値シミュレーションで実測しました（母音的モジュレーター −0.9dBFS、キャリア=Saw 130Hz、
CHARACTER=1.0 / RESONANCE=1.0 / OUT LEVEL=0dB / MIX=100% の既定値）。

### 3-1. 実測結果（現行コード）

| BANDS | 出力ピーク | 0dBFS 超えのサンプル比率 |
|---|---|---|
| 48（既定）| **+6.15 dBFS** | **29.7 %** |
| 32 | +5.71 dBFS | 36.0 % |
| 24 | +6.17 dBFS | 26.6 % |
| 16 | +11.30 dBFS | 42.6 % |
| 8 | **+16.38 dBFS** | 50.9 % |

**既定設定で全サンプルの約3割が 0dBFS を超えています。** LIMIT が拾ってはいますが、
BrickLimiter はリリース 120ms なので 6dB ぶん常時ゲインを引かれ続け、
「ポンピング + 潰れ」として聞こえます。これが「簡単にクリップする」の正体です。

### 3-2. 原因1: メイクアップゲインが約 +12dB 過大
`FilterbankVocoder.h:120`
```cpp
static constexpr float kBpfMakeup = 32.36f;
```
コメントには「旧実装と同一の最終音量になるよう等価換算」とありますが、
**旧実装のレベル自体が過大だった**ため、そのまま引き継がれています。

ユニティ検証（キャリア＝モジュレーターの自己ボコード。理想は入力＝出力）:
```
BANDS=48:  入力 -10.85 dB → 出力 +0.23 dB   （+11.1 dB の過剰ゲイン）
```

### 3-3. 原因2: バンド数補償の式が間違っている
`FilterbankVocoder.cpp:186`
```cpp
const float bandComp = std::sqrt((float)kMaxBands / (float)activeBands);
```
「バンドが少ないほどオーバーラップ加算が減るから持ち上げる」という前提ですが、
**実測ではバンド数を変えても素の合成レベルはほぼ変わりません**（48バンド基準で ±2dB 以内）。

```
Saw130 : b=8:+1.4dB  b=12:+1.7dB  b=16:+0.1dB  b=24:-1.8dB  b=32:-0.7dB  b=48:0.0dB
```
つまり `sqrt(48/8)=2.45` = **+7.8dB を根拠なく足している**のが、8バンドで +16dBFS まで
暴走する原因です。補償は撤廃するのが正解です。

### 3-4. 原因3: CHARACTER 既定値でビビり音が最大になる
`FilterbankVocoder.h:103-104`
```cpp
float att = 0.005f + character * 0.045f;
float rel = 0.001f + character * 0.009f;
```
CHARACTER=1.0（**既定値**）のとき att τ=1.2ms / rel τ=**6.3ms**。
130Hz の声のピッチ周期は 7.7ms なので、**エンベロープが基音の1周期ごとに落ちきってしまう**。
これが振幅変調となって「ビビり／ザラつき」になります。

実測したエンベロープのリップル比（低域バンド）:
```
CHARACTER=0.00 → 0.04    CHARACTER=0.50 → 0.18    CHARACTER=1.00 → 0.29
```
本来ボコーダーの検波リリースは**バンド中心周波数に応じて変える**べきです
（低域ほど長く。最低でも基音周期の2〜3倍）。現行は全48バンド一律です。

### 3-5. 原因4: 交互ハードパン
`PluginProcessor.cpp:833` で `stereoWidth` に **1.0 固定**が渡され、
`FilterbankVocoder.cpp:166-176` で高域バンドは `theta` が 0°/90° に振り切ります。
つまり**高域は偶数バンドが完全L・奇数バンドが完全R**。

```
L/R 相関 = +0.017（ほぼ無相関）
L単独ピーク +6.15dB / モノ和ピーク +2.01dB  → モノ化で -4dB & 音色変化
```
モノ互換性が事実上ありません。width は 0.4〜0.6 程度に抑えるか、パラメータ化すべきです。

### 3-6. 改修案と検証結果
以下の4点を同時に適用してシミュレーションし直しました。

1. `kBpfMakeup` : **32.36 → 8.0**（−12.1dB）
2. `bandComp` : **撤廃**（常に 1.0）
3. エンベロープ検波を**バンド毎リリース**に変更
   （att: 0.5〜10.5ms / rel: `max(CHARACTER依存, 2.5周期ぶん)`）
4. `stereoWidth` : **1.0 → 0.6**

| BANDS | 現行ピーク | 改修後ピーク | 現行リップル | 改修後リップル |
|---|---|---|---|---|
| 48 | +6.15 dB | **−4.84 dB** | 0.28 | **0.10** |
| 32 | +5.71 dB | −7.51 dB | 0.23 | 0.10 |
| 24 | +6.17 dB | −9.19 dB | 0.29 | 0.11 |
| 16 | +11.30 dB | −6.02 dB | 0.35 | 0.13 |
| 8 | +16.38 dB | **−1.38 dB** | 0.44 | **0.18** |

自己ボコード・ユニティも回復（入力 −10.85dB → 出力 −11.43dB ≒ ユニティ）。
CHARACTER を上げたときの高域の追従（明瞭度）は保たれています（高域リップル 0.05→0.43 で
CHARACTER の効きは残る）。

### 3-7. LPC モードのレベル
`LpcVocoder.h:38` `kMakeupGain = 0.918f` は「Ableton 実測 +6.76dB を差し引いてユニティ化」と
記録されており、Filterbank ほど過大ではありません。ただし既知の未解決点が残っています。

- **LPC ORDER によるレベル差 +8.7dB**（過去の監査で計測済み・判断保留のまま）。
  Order 8 → 16 でゲインが跳ねます。`analyzeFrame` の返す `G = sqrt(E_P)` は
  次数が上がるほど残差エネルギー E_P が小さくなる一方、フィルタ 1/A(z) の利得は増えるため、
  `weightedEnergy()` による補償を **Order 変更時にも適用する**必要があります
  （現在は FMT STRETCH と K QUANT のときだけ補償している）。
- **デエンファシス `1/(1-0.9375 z⁻¹)` に DC ブロッカーが無い**（`LpcVocoder.cpp:480-481`）。
  DC 利得は 16倍（+24dB）。キャリアにカスタム Wavetable を使うと DC オフセットが
  16倍に増幅されて低域が膨らみ、最悪ラティスを飽和させます。
  → 出力段に fc=20Hz の1次ハイパスを入れるだけで解決します。

## 4. 安定性・堅牢性

### 4-1. ★★☆ 配列の範囲外読み出し（PluginProcessor.cpp:917-922）
```cpp
int idx0 = (int)mUpsampleTimeAccum;
int idx1 = std::min(num16kSamples - 1, idx0 + 1);
writeL[i] = m16kWetL[(size_t)idx0] * ... + m16kWetL[(size_t)idx1] * frac;
```
`num16kSamples == 0` のとき `idx1 = -1` となり、`(size_t)(-1)` = 巨大値でアクセス → **クラッシュ**。
`num16kSamples` は、ホストブロックが `hostSR/16000`（48kHzで3サンプル）より小さいときに
0 になり得ます。サンプル精度オートメーションでブロックを刻むホストや、
一部のバウンス処理で実際に発生します。
`idx0` 側にも上限クランプがありません。
→ 対策: `didProcess` の条件に `num16kSamples > 0` を加え、`idx0` を `jlimit(0, num16kSamples-1, ...)` する。

### 4-2. ★★☆ use-after-free（ValueKnob.h:41-51）
```cpp
auto& box = juce::CallOutBox::launchAsynchronously(...);
edPtr->onReturnKey  = [this, edPtr, &box] { ...; box.dismiss(); };
edPtr->onFocusLost  = [&box] { box.dismiss(); };
```
`onReturnKey` で `box.dismiss()` → CallOutBox が delete される →
その直後に瀕死のエディタから `onFocusLost` が発火 → **解放済みメモリへ `dismiss()`**。
Enter で確定したときに確率的に落ちます。
→ 対策: `juce::Component::SafePointer<juce::CallOutBox>` で保持し、null チェックしてから dismiss。

### 4-3. ★☆☆ NaN / Inf ガードが無い
出力経路（FilterbankVocoder / LpcVocoder / FxChain / ExcitationEngine）に `isfinite` チェックが
ありません。`AnalyzerDSP.h:109` にだけ存在します。
LPC のラティスや Resonator のフィードバックで一度 NaN が発生すると、
**リセットするまで永久に無音（または轟音）**になります。
→ 対策: `processBlock` の最終段（リミッター直前）で1回だけ
`if (!std::isfinite(x)) { 全DSPをreset(); バッファclear(); }` を入れるのが安価で確実です。

### 4-4. ★☆☆ 入力が無いと LFO/ENV が停止する
`mModMatrix.processBlock()` は 16kHz ループの中でしか呼ばれません（PluginProcessor.cpp:699）。
入力チャンネルが 0、または `num16kSamples == 0` のとき **変調が完全に止まります**。
MIDI モードで入力を繋がずに使うと LFO が動かない、という症状になります。
（参照実装の Wavetable は「グローバルクロック」を別に持ち、無音でも回し続けています）

### 4-5. ★☆☆ AnalyzerDSP のバックグラウンドスレッド
`AnalyzerDSP.cpp:104` `mLocal.resize()` — 表示用スレッドなのでリアルタイム安全性は問題なし。
ただし `juce::ScopedNoDenormals` が無いため、包絡が −100dB 付近を漂うと
デノーマル演算で CPU を余計に食います（実害は小）。

### 4-6. 問題なしと確認できた箇所
- `ScopedNoDenormals` はオーディオスレッドに適用済み（PluginProcessor.cpp:519）。
- `prepareToPlay` で全バッファを事前確保、`processBlock` 内にアロケーションなし。
- `setStateInformation` の BAND_EQ_GAINS ノード増殖対策・NaN 丸めは適切。
- `WeakReference` によるカスタム Wavetable 非同期ロードのダングリング防止は正しい。
- `BrickLimiter` は数学的に天井以下を保証しており、実装は正しい。

## 5. LFO の検証（Wavetable / PicoSampler との比較）

### 5-1. 質問への直接の回答: サイクル間の「間」は**ありません**
`ModMatrix.h:284-289`
```cpp
st.phase += inc;
while (st.phase >= 1.0) { st.phase -= 1.0; st.shValue = ...; }
```
1.0 を超えた分を差し引く連続ラップなので、周期の切れ目に空白は生じません。
参照2機種（`Wavetable/Source/Logic/Lfo.h:101-110`、`PicoSampler/Source/DSP/ModMatrix.h:286-295`）
と**同一方式**です。この点は問題ありません。

### 5-2. ★★★ ただし LFO レートが 1/3 になっています【致命】
`PluginProcessor.cpp:446`
```cpp
mModMatrix.prepare(sampleRate);   // ← ホストレート(例 48000) を渡している
```
`PluginProcessor.cpp:699`
```cpp
mModMatrix.processBlock(32, mModParams);   // ← 16kHz ループの中から呼んでいる
```
`ModMatrix.h:281` の位相進みは `freq * numSamples / sampleRate` = `freq * 32 / 48000` ですが、
実際の制御ティックは **16kHz の 32サンプル毎 = 500回/秒**です。
したがって実測レートは `設定値 × 16000 / ホストSR` になります。

| ホストSR | 設定 1.0Hz の実測 | 倍率 |
|---|---|---|
| 44.1 kHz | 0.363 Hz | ×0.363 |
| **48.0 kHz** | **0.333 Hz** | **×0.333** |
| 88.2 kHz | 0.181 Hz | ×0.181 |
| 96.0 kHz | 0.167 Hz | ×0.167 |

**テンポ同期も同じ倍率でズレます**（1/4 を選んでも DAW のグリッドに乗りません）。
また **ENV1/ENV2 も同じ式**（`ModMatrix.h:301` `blockSec = numSamples / sampleRate`）なので、
アタック/ディケイ/リリースも 3倍遅くなっています。

→ 対策は1行です。`mModMatrix.prepare(LpcVocoder::kInternalSampleRate);` に変更してください。
（PicoSampler では ModMatrix がホストレートのループから呼ばれているので整合しており、
 SPECTRA8 で 16kHz ループへ移植した際に prepare の引数だけ直し忘れた、という形です）

### 5-3. 参照実装にあって SPECTRA8 に無い機能
| 機能 | Wavetable | SPECTRA8 |
|---|---|---|
| フリーラン用グローバルクロック | あり | 無し（4-4 の停止問題） |
| `isfinite(phase)` ガード | あり（Lfo.h:111） | 無し |
| 1ブロック内多周回のラップ回数制限 | あり（8回上限） | 無し（`while` 無制限＝高レート時にスピン） |
| SMOOTH（出力1極LPF） | あり | 無し |
| DELAY（掛かり始めまでの時間） | あり | 無し |
| トリガーモード（Free/Retrig/One-Shot） | あり | 無し（常時フリーラン） |
| 位相の double 累積 | あり | あり ✓ |

制御レート 2ms なので、LFO 出力は 2ms の階段状です（500Hz サンプリング相当）。
50Hz の LFO だと 1周期あたり 10ステップしかなく、変調先によってはジリつきます。

## 6. その他のアルゴリズム欠陥

### 6-1. FxChain
- `FxChain.h:874` — `sp.amount <= 0.0001f` のときスロットを **完全にスキップ**しています。
  つまり Amount=0 では Reverb / Resonator の内部状態が凍結し、Amount を戻した瞬間に
  古い残響が復活してポップします。`PluginProcessor.cpp:932` のコメント
  「MIX=0 でもFX自体は動かし続ける」という意図と矛盾しています。
  → 対策: 状態は常に更新し、出力ミックスだけ 0 にする。
- スロットの Type 変更にクロスフェードが無いため、FX を差し替えると必ずプツッと鳴ります。
- D&D で並べ替えると Type/Amount の値が入れ替わりますが、**各FXの内部状態は入れ替わらない**ため
  並べ替え直後に残響が飛びます。

### 6-2. ExcitationEngine
- `ExcitationEngine.cpp:573` `voiceScale = 1/sqrt(activeVoiceCount)` — Auto モードでは常に
  3ボイス固定なので問題ありませんが、MIDI モードでは**発音数が変わるたびにゲインが跳びます**
  （1音→2音で −3dB）。スムージングが必要です。
- `ExcitationEngine.cpp:559` Morph Vocode の `wetL * 4.0f` — 3基のBPF出力を単純加算した上で
  4倍しています。VOCODE=1.0 かつ共振が重なると容易にクリップします（上限クランプ無し）。
- `applyLoFi()` の S&H は L/R で**同一のカウンタ**を共有しているため、
  デチューンで L/R の位相が違ってもホールドタイミングは同じ = ステレオ感が潰れます。
- `mRng`（`juce::Random`）を毎サンプル2回呼んでノイズを生成。RT安全ではありますが、
  `juce::Random` は LCG なので L/R が同じ系列から交互に出ており、**L/R のノイズに相関があります**。
  ノイズ100%時のステレオ感が狭くなる原因です。

### 6-3. PitchTracker
- `analyze()` は 1ホップ（16kHzで128サンプル = 8ms）ごとに、NSDF を約 12万回の積和で計算します。
  これが**オーディオコールバックの1サンプル処理の中で同期実行**されるため、
  該当ブロックだけ CPU が跳ねます（平均負荷は低いがピークが立つ）。
  小さいバッファサイズで使うとドロップアウトの一因になり得ます。
- ロジック自体（ゼロ交差条件、3フレームメディアン、証拠ベースのオクターブ補正、
  シュミットトリガー）は適切に修正済みで、欠陥は見当たりません。

### 6-4. ModMatrix
- `ModMatrix.h:365` `destAccum[dst] += v * s.amt;` — 複数スロットが同じ宛先を指すと
  単純加算され、上限クランプがありません。`applyMod` の `KindExpOct` 側は
  `base * pow(2, modVal * s)` なので、2スロットで Base Pitch を +1.0 ずつ変調すると
  `pow(2, 4.0)` = 16倍。`jlimit` は後段に効きますが、**変調量そのものは無制限**です。
- LFO の位相ラップ `while (st.phase >= 1.0)` に回数上限がありません。
  `inc` が NaN になると**無限ループでオーディオスレッドが固まります**（Wavetable 版は8回上限）。

### 6-5. FilterbankVocoder
- `processSample()` 冒頭で毎サンプル `rebuildLayout()` を呼んでいます。
  同数なら即 return するので実害は小さいですが、分岐が1本無駄です。
- `mBandEdges` / `mBandQ` はバンド数変更時のみ再計算されますが、**RESONANCE は
  毎サンプル乗算**されるため、Q が跳ぶと `1/(Q*Q)` の正規化も跳び、
  レベルが不連続に動きます（2-2 参照）。

### 6-6. PostBandEq
- `PluginProcessor.cpp:646` でブロック毎に `updateCoeffs()` を呼んでいます。
  BANDS EQ をドラッグ中はブロック単位の階段になります（3の EQ ゲイン問題と同根）。
