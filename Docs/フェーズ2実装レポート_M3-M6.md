## M4: フルホップ補間（2026-07-14 実装）

従来は制御ブロック(32smp=2ms)の高速ランプでkがターゲットへ即到達し、低フレームレートでは
ステップ状の「トイ感」になっていた。これを**フレーム間のホップ全長を掛けた補間**に拡張し、
`interpolationMode` パラメータで切替可能にした。

- **Step** (既定): 従来動作。旧実装とビット完全一致を回帰テストで確認済み。レトロ系プリセット向け。
- **LSP**: 線スペクトル周波数領域で端点をlerp。フォルマント軌跡が自然。Hi-Fi/Vintageプリセット向け。
- **LAR**: 対数面積比(atanh k)領域でlerp。軽量で滑らか。

設計要点:

- セグメント端点は「現在の平滑値 mKCur → 新フレームターゲット」。フレーム境界での不連続なし。
- LSP変換失敗(根喪失)時はLARへ自動フォールバック。step-down失敗時はkドメインlerpへ。
- 補間値の算出は制御ブロック毎(500Hz)、ブロック内は従来同様の線形ランプ(常時 |k|<1 保証)。
- 連続するLSPセグメントでは前端点のrepr(LSF)を引き継ぎ、変換回数を1回/フレームに削減。
- モード変更は次の分析フレームから適用(最大125ms@8Hz)。

検証結果 (g++スタブ、4秒信号):

- 平滑性: @8Hz order16 の1サンプル最大k変化 Step=0.043 → LSP=0.0028 → LAR=0.0009
- 安定性: 全設定スイープ(order×frameRate×quant×interp×shift×stretch)でNaN/Infゼロ・有界
- 回帰: Step時は旧版(git 3833b49)とハッシュ完全一致(6設定)

## M6: CPU計測と最適化

`LspConverter::evalG` のcos/sin列を角度加算漸化式に変更(trig呼び出し 2L回→4回)、
二分法を60→40回に削減。LSP系機能(FMT STRETCH含む)が約4倍高速化。

| 設定 (order16, 内部16kHz) | 最適化前 | 最適化後 |
|---|---|---|
| Step (=旧動作) | 0.15% | 0.15% |
| LSP補間 @50Hz | 5.3% | 1.4% |
| LSP補間+STRETCH1.3 @80Hz (最悪) | 22.3% | 4.8% |
| LAR補間+STRETCH1.3 @80Hz | 8.4% | 2.2% |

※ CPU% は1コア換算。LSP往復精度は最適化後も worst 3e-8 (Done条件 1e-3)。

また `setupSegment` の端点repr再利用判定にオフバイワンがあり(ホップ長が32の倍数でないと
毎フレーム二重変換)、`mSegPos + kCtrlBlock >= mSegLen` に修正。

- `interpolationMode`: 選択肢 {LSP, LAR} → **{Step, LSP, LAR}** 既定0=Step。
