# SPECTRA8 フェーズ2 実装計画書 v2 — LPCモード（BitSpeek系アルゴリズム）

作成日: 2026-07-12 / 基準: 過去の失敗分析 + Web技術調査 + BitSpeek公式マニュアル精読

---

## 0. 結論サマリ（最重要）

過去のLPC実装が失敗し続けた根本原因は **「LSP中心の過剰設計」** にある。
本計画では方針を根本転換する：

> **合成フィルタは「ラティス（格子）フィルタ＋反射係数 k」で駆動する。**
> **LSPは安定化のためには一切不要。** 反射係数は |k| < 1 であれば数学的に安定が保証され、
> クランプ1行で完全な発振防止ができる。これは Speak & Spell の音声チップ TMS5220 が
> ハードウェアで採用していた実証済みの方式であり、BitSpeekの音の正体もこの系譜である。

LSPは「フォルマント・ストレッチ」等の高度な変形専用のオプション（後期マイルストーン）に降格する。

## 1. 過去の失敗の根本原因分析（git履歴 fed2a69 等の実コード検証による）

| # | 失敗原因 | 証拠 | 対策 |
|---|---|---|---|
| 1 | **毎サンプルの LSP→LPC 逆変換＋ワーピング**。16係数×(acos+sin+cos+atan)を毎サンプル実行 → CPU爆発と数値誤差の蓄積 | 旧PluginProcessor.cpp 800行目付近 | ラティス化により逆変換そのものを廃止 |
| 2 | **符号規約の混乱**。A(z)=1+Σa_k z^-k と 1-Σa_k z^-k の流儀が混在し「極性反転の整合」修正を繰り返した | コミット f785511「極性反転バグの修正」等 | 計画書に唯一の基準式を明記(§5)。kのみ扱いLPC係数aを合成に使わない |
| 3 | **直接形IIRの係数を時変で駆動**。端点が安定でも補間途中で不安定化しうる | 旧実装全体 | ラティスは補間途中の全点で\|k\|<1 → 常時安定 |
| 4 | **モノリシックAVX2コードに埋没**。分析・合成・GUI・EQが1ファイルに絡み単体テスト不能 | 旧PluginProcessor.cpp(1195行) | 独立モジュール LpcEngine として実装、スタブ環境で単体検証 |
| 5 | **オフライン検証の欠如**。DAW上の耳デバッグのみで数値的裏付けなし | 「音が出ない」「全くだめ」コミット | M0でPythonプロトタイプ→ゴールデンテスト→C++移植の順を厳守 |
| 6 | 帯域拡張 γ=0.96 が強すぎフォルマントがぼやける | 旧コード | γ=0.990〜0.996（コーデック実務標準）に変更 |

## 2. Docs既存資料の信頼性評価

**「Real-Time LPC LSP Conversion.txt」**: LSPの数学（交互配置性、Chebyshev展開、Kabal法）自体は
学術的に正確（Kabal & Ramachandran 1986 と一致）。ただし①192kHz前提の文書でSPECTRA8の16kHz内部
処理とは前提が違う、②「LSP逆変換を毎サンプル実行」というアーキテクチャ推奨が失敗原因#1そのもの。
**→ 数学の参考書としては有効、設計指針としては採用しない。** M4(LSP導入時)にのみ参照する。

**開発計画書第2版のLPC節**: 自己相関法・Levinson-Durbin・|k|≤0.98制限・帯域拡張は正しい方向。
ただしγ=0.96は強すぎ。LSP最小ギャップ補正はM4でのみ必要。

## 3. 外部調査で得た確定知見

### 3.1 BitSpeek の正体（公式マニュアル v1.0.2 精読）
- **ピッチ励起LPC（PELP）**: 入力をフレーム毎に「ピッチ・音量・フォルマント(フィルタ)・有声/無声バランス」
  の4種パラメータに分解し、**オシレーター＋ノイズ＋フォルマントフィルタ**で再合成する。キャリア入力不要の
  パラメトリック方式。
- **内部レート切替 (8/11/22/44kHz)**: 音を劇的に変えるキャラクター選択。低レート＝トイ感。
- **FRAME RATE 0〜80Hz**: 下げるほど安っぽく（トイ的）、**0でフリーズ**。テンポ同期(1/8,1/16等)可。
- MIDIモード（Tracking 0%でボコーダー的）、Tracking 0〜200%、Pitch ±36st、Detune 0〜+1200セント、
  Noise ±100%（-100%=ノイズ除去、+100%=全ノイズ＝ウィスパー）、**レイテンシ13ms固定・モノフォニック**。
- → SPECTRA8には tracking / detune / noise / pitchQuantize / basePitch / MIDIモード / freeze が
  **既に存在**。フェーズ2の追加UIは実質 FRAME RATE と ORDER のみで BitSpeek を包含できる。

### 3.2 TMS5220（Speak & Spell系チップ）の合成方式
- パラメータ: Pitch, Energy, **K1〜K10（反射係数）** を25msフレーム毎に更新。
- 合成は**10段ラティスフィルタ**＋励起（有声=グロッタルパルスROM / 無声=LFSRノイズ）。
- 反射係数は「有界性により安定な合成フィルタを保証する」— 我々の方針の直接の裏付け。

### 3.3 音声コーデック実務の定石（分析の数値衛生）
- **白色雑音補正**: r(0) ×1.0001〜1.004（-40dB程度のノイズフロア注入）で Levinson-Durbin の
  悪条件を回避。
- **ラグウィンドウ**: 自己相関列にガウス窓（標準偏差40〜60Hz相当）を乗じてスペクトルを平滑化。
- **帯域拡張**: a_k ← a_k·γ^k、γ≈0.994（60Hz展開）が標準。
- **LPC次数の経験則**: fs(kHz)+2。16kHz→次数16〜18が上限目安。LPC10は8kHzで次数10。

### 3.4 JUCEフォーラムの先行事例（2025年のBitSpeekクローン挑戦スレ）
- 失敗要因は「processBlock内での大量のstd::vector確保」と性能問題 — RTセーフの事前確保は
  SPECTRA8フェーズ1で確立済みの流儀を踏襲すれば回避可能。

## 4. 新アーキテクチャ設計

### 4.1 信号フロー（vocoderMode = LPC 時）

```
入力(モジュレーター) → [16kHzダウンサンプル(既存)] → リングバッファ
                                    │ フレーム毎 (FRAME RATE Hz)
                                    ▼
                      ┌─ LpcAnalyzer ─────────────────┐
                      │ 窓掛け(windowType: Hann/Hamming/│
                      │  Blackman) → 自己相関(+白色雑音 │
                      │  補正+ラグ窓) → Levinson-Durbin │
                      │  → 反射係数k[1..P] + ゲインG    │
                      └───────────────┬───────────────┘
                                      │ ターゲット値(フレーム毎)
PitchTracker(既存) → ピッチ/VUV        │
ExcitationEngine(既存) → キャリア ──┐  ▼
                                  │ [kとGをコントロールブロック毎に線形補間]
NOISE(既存, BitSpeek式±で拡張) ──→ 励起ミックス
                                  │  ▼
                                  └→ LpcLattice(P段格子) → ゲイン → 出力
                                        (毎サンプル、|k|<1で常時安定)
```

### 4.2 新規モジュール（Source/DSP/ 配下、各200行以下目標）

| ファイル | 責務 |
|---|---|
| `LpcAnalyzer.h/.cpp` | フレーム化・窓・自己相関・Levinson-Durbin。出力: k[P], gain, E |
| `LpcLattice.h` | 全極ラティス合成フィルタ（ヘッダオンリー、状態P個、毎サンプルO(P)） |
| `LpcVocoder.h/.cpp` | 上記の統括。補間、V/UVミックス、フリーズ、FilterbankVocoderと同一のI/F |

**PluginProcessor への変更は「vocoderMode で FilterbankVocoder / LpcVocoder を切り替える分岐＋
30msクロスフェード」のみ**。フェーズ1の安定資産には触れない。

## 5. 数理仕様（符号規約の唯一の基準）

### 5.1 基準式（これ以外の流儀を持ち込まない）
- 予測: x̂(n) = **−**Σ_{i=1..P} a_i·x(n−i)、逆フィルタ A(z) = 1 + Σ a_i z^{−i}
- ただし**合成には a_i を使わない**。Levinson-Durbin の副産物である反射係数 k_i のみを出力する。

### 5.2 分析（LpcAnalyzer、フレーム毎）
1. 窓掛け: w(n)·x(n)、窓長N=256（16ms@16kHz）、ホップはFRAME RATE依存（既定50Hz→320smp）
2. 自己相関: r(j) = Σ x_w(n)x_w(n+j) (j=0..P)
3. **数値衛生**: r(0) ← r(0)×1.0001 + 1e-9（白色雑音補正）、r(j) ← r(j)·exp(−½(2πσj/fs)²) σ=50Hz（ラグ窓）
4. Levinson-Durbin: 各段の k_i = (r(i) − Σa_j r(i−j))/E_{i−1}、**k_i を [−0.995, +0.995] にクランプ**、
   E_i = E_{i−1}(1−k_i²)。E が 1e-9 未満になったら以降 k=0 で打ち切り（前フレーム保持はしない）
5. ゲイン: G = √E_P（残差エネルギー）→ 出力音量の自動整合（フェーズ1の「ゲインマッチング」を実現）
6. 無音フレーム（r(0)<閾値）: k を全て 0 へ目標設定（フィルタ透過化）、G→0

### 5.3 合成（LpcLattice、毎サンプル）
```
入力 u(n) = G·(キャリア/ノイズミックス)
f = u(n)
for i = P..1:  f = f − k_i·b[i−1];  b[i] = k_i·f + b[i−1]   // b[]は前サンプルの値
y(n) = f;  b[0] = f
```
- 安定条件: 全ての |k_i| < 1（クランプ済みなので**構造的に発振不可能**）
- 補間: コントロールブロック（32smp）毎に k_i と G をターゲットへ線形ランプ。
  線形補間途中の k も |k|<1 を満たすため常時安定（LSP不要の根拠）
- デノーマル対策: juce::ScopedNoDenormals（既存）+ b[] に1e-20注入

### 5.4 フォルマントシフト（M3、LSP不要の方式）
分析への入力デシメーション比を 2^(shift/12) 倍にスケール（=分析レートの実効変更）。
分析が「速回し/遅回し」された声道形状を合成が16kHzで再生する事でフォルマントが物理的にシフトする。
テープ変速と同原理で、BitSpeekのRate切替と同じ音響効果。フィルタ係数の数学的変形が一切不要。

## 7. リスク対策マップ

| リスク | 対策 |
|---|---|
| フィルタ発振・爆音 | ラティス+kクランプで構造的に排除。最終段に既存BrickLimiter |
| 符号規約バグ再発 | §5.1を唯一の基準とし、aを合成に使わない設計で被害面を消す |
| CPU過負荷 | ラティスは16kHz×P=16段=25万mul/s程度と超軽量。分析はフレーム毎(≤80Hz)のみ |
| フレーム境界のクリック | k/Gのブロック線形補間＋ゲインGの平滑化(att 5ms/rel 30ms) |
| ピッチ誤検出（オクターブ跳ね） | フェーズ1.5で実装済みのPitchTracker補正をそのまま利用 |
| LSP変換の根喪失（M4） | ルート数≠Pなら当該フレームを破棄し前フレーム保持（連続破棄カウンタで劣化検知） |
| モード切替のポップ | 30ms等パワークロスフェード（旧実装f51f352の知見を流用） |
