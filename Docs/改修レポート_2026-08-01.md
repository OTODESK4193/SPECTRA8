## ① LFO / ENV のレート修正

`PluginProcessor.cpp` — `mModMatrix.prepare(sampleRate)` → `prepare(LpcVocoder::kInternalSampleRate)`。

`ModMatrix::processBlock(32, …)` は 16 kHz ループから呼ばれる（制御ティック 500 回/秒）のに、
位相の進みは `freq × 32 / ホストSR` で計算されていたため、実レートが `16000 / ホストSR` 倍に
なっていた。

実測（Saw 波の周期を 40 秒平均でカウント）:

| 設定 | 改修後 | 改修前 @48kHz | 改修前 @96kHz |
|---|---|---|---|
| 0.5 Hz | 0.47 | 0.15 | 0.07 |
| 1.0 Hz | 0.97 | 0.33 | 0.15 |
| 2.0 Hz | 1.98 | 0.65 | 0.33 |
| 5.0 Hz | 4.97 | 1.65 | 0.82 |

ENV も同じ式なので同時に直っている（Attack 0.5s / Decay 0.5s の LOOP が実測 1.000 秒周期）。
テンポ同期も DAW のグリッドに乗るようになった。

**追加で見つかった不具合**: LOOP を点けた ENV は `Idle` から出られず、MIDI ノートを
弾かない限りまったく動かなかった。Auto モードで「4つ目の LFO」として使えるよう、
LOOP 時は Idle から自動で立ち上がるようにした。

## ② Filterbank のレベル改修

### 変更点
1. `kBpfMakeup` **32.36 → 8.0**（−12.1 dB）
2. `bandComp = sqrt(48/bands)` を**撤廃**（実測でバンド数によるレベル差は ±2 dB 以内＝補償不要）
3. 検波（エンベロープ追従）を**バンド毎リリース**へ変更
4. `stereoWidth` を **1.0 固定 → WIDTH ノブ（既定 0.6）**として新設

### 検波の設計
```
アタック : 1.5 ms（CHARACTER=1.0）〜 13.5 ms（CHARACTER=0.0）
リリース : max( 8 ms〜68 ms（CHARACTER依存）, 2.5 / (0.35×f0) )
```
リリース下限は f0=100 Hz で約 42 ms、7 kHz で約 1.0 ms。低域ほど長く保持することで、
検波が声の基音周期ごとに落ちきって振幅変調（＝ビビり音）になるのを防ぐ。
高域は下限が緩いので子音のキレ（CHARACTER の効き）は残る。

> **途中で方針を修正した点**: 最初はアタックを 0.5 ms まで速くしたが、声門パルス1発ごとに
> 検波が跳ね上がり、実測でビビりが 0.0305 と**改修前（0.0295）より悪化**した。
> 定数を掃引して測り直し、1.5 ms が最良点だった（立ち上がりの鈍りは +1.1 ms のみ、
> ビビりは 0.0223）。3 ms まで遅くすればビビりは半減するが立ち上がりが 17.9 ms になり
> 子音がぼやけるため採用しなかった。

### CHARACTER が効くようになった
改修前は CHARACTER をどこにしてもビビり量がほぼ変わらなかったが、
改修後は**ノブでビビりを消せる**ようになった。

| CHARACTER | 1.00 | 0.75 | 0.50 | 0.25 | 0.00 |
|---|---|---|---|---|---|
| 検波リップル | 0.0223 | 0.0084 | 0.0051 | 0.0036 | 0.0028 |

### WIDTH ノブ
0.0＝完全センター（モノ互換）〜 1.0＝旧来の振り切り。既定 0.6。
MOD MATRIX の変調先（"Width"）にも追加した。VOCODER タブの上段、RESONANCE の隣に配置
（Filterbank モードのみ表示）。

## ③ クラッシュ要因の除去

- **範囲外読み出し** (`PluginProcessor.cpp`): `num16kSamples == 0` のとき `idx1 = -1` になり
  `(size_t)(-1)` で巨大インデックスになっていた。`didProcess` の条件に
  `num16kSamples > 0` を追加し、さらに `idx0`/`idx1`/`frac` を範囲内へクランプ。
  アキュムレータの暴走も丸めるようにした。
- **use-after-free** (`ValueKnob.h`): `CallOutBox` を `&box` で生キャプチャしていたため、
  Enter 確定 → `dismiss()` で解放 → 直後に `onFocusLost` が解放済みメモリへ `dismiss()`。
  `juce::Component::SafePointer<juce::CallOutBox>` で保持し、生存確認してから閉じるように変更。

## ④ 堅牢化

- **NaN / Inf の水際チェック**: ブロック末尾で出力を検査し、非有限値が出たら全 DSP を
  reset して無音で返す。一度 NaN が入ると永久に復帰しない問題を解消。
- **LFO 位相ラップの上限**: `while (phase >= 1.0)` に 8 回上限と `isfinite` ガードを追加。
  rate が NaN になるとオーディオスレッドが無限ループで固まっていた。
  （rate=NaN で 1000 ティック完走・出力有限を確認）
- **変調値のクランプ**: `ModMatrix::get()` で `isfinite` チェック＋±4 に制限。
- **入力が無くても変調が動く**: `ModMatrix` は 16 kHz ループ内でしか回っていなかったため、
  入力チャンネルが 0 のとき LFO/ENV が完全停止していた。経過時間ぶんを別途進めるようにした。
- **オーディオスレッドからヒープ確保を排除**（監査時には気付いていなかった重大な問題）:
  制御ティックごとに `"slot0src"` のような `juce::String` を組み立てており、
  **毎秒約 5,500 回のヒープ確保**がオーディオスレッドで走っていた。
  全パラメータポインタを `prepareToPlay` で一度だけキャッシュするよう変更。
  `moddedParam()` の文字列ハッシュ検索（毎秒約1万回）も同時に解消。

## ⑤ スムージングの一括導入

- **全 26 変調宛先**に 1 極平滑（τ≈5 ms）を導入し、16 kHz ループの毎サンプルで進める。
  RESONANCE / CHARACTER / M.PITCH / BASE PITCH / NOISE COLOR / LOFI / WT POS などの
  2 ms 階段がすべて解消。FMT SHIFT/STRETCH の二重平滑も解消した。
- **BANDS 切替**: `rebuildLayout()` 内の `reset()` で必ずクリックが出ていたので、
  10 ms フェードアウト → 再構築 → 10 ms フェードインに変更（不連続量 0.4181 → 0.0914）。
- **BANDS EQ の帯域ゲイン**: Filterbank 側は τ≈10 ms のサンプル単位平滑、
  LPC 側（PostBandEq）は τ=20 ms のブロック単位平滑。ドラッグ中のジッパーを解消。
  PostBandEq のレイアウト変更時の状態リセットも撤廃（連続性を保つ方が滑らか）。
- **LIMIT ボタン**: 瞬時分岐 → 20 ms クロスフェード。
- **FX 全パラメータ**: τ=30 ms のブロック単位平滑（後述）。

## ⑦ LPC の Order レベル差と DC ブロッカー

### 励起ゲインを「レベル整合方式」へ変更
旧: `G = sqrt(E_P)`（残差 RMS）。次数を上げるほど E_P は小さくなる一方 `1/A(z)` の利得は
増え、両者が相殺しないため ORDER を変えるだけで音量が動いていた。

新: そのフレームの平均二乗値に合わせる。
```
G = sqrt( (r0 / Σw²) / wE )       wE = 励起重み付きフィルタエネルギー
```
定義上 ORDER に依存せず、入力のダイナミクスもそのまま保たれる
（シミュレーションで Order 間差 0.00 dB、入力 −20 dB → 出力 −20 dB を確認）。

実コードでの ORDER 別 rms:

| | Order 8 | 10 | 12 | 16 | 最大差 |
|---|---|---|---|---|---|
| 改修前 | −5.25 | −4.10 | −5.66 | −10.14 | **6.04 dB** |
| 改修後 | −11.82 | −11.94 | −11.67 | −10.34 | **1.60 dB** |

残る 1.6 dB は、キャリア（Saw 130 Hz）の倍音が Order 16 の鋭い極に当たるかどうかという
信号依存の成分で、原理的にゼロにはならない。

`kMakeupGain` は 0.918 → **0.259** に再較正（新方式で G が約 +11.0 dB 大きくなるため）。
Order 16 の音量は改修前 −10.14 dB → 改修後 −10.34 dB とほぼ変わっていない。

### DC ブロッカー
デエンファシス `1/(1−0.9375z⁻¹)` は DC 利得 16 倍（+24 dB）。キャリア（特にカスタム
Wavetable）の僅かな DC が増幅されて低域が膨らむため、出力に fc=20 Hz の 1 次ハイパスを追加。

## ⑧ FX のクロスフェードとパラメータ平滑

- **Amount=0 でも FX 本体を動かし続ける**ようにした。旧実装は丸ごと skip していたため
  リバーブ/レゾネーターの状態が凍結し、Amount を戻した瞬間に古い残響が復活していた。
- **Amount をサンプル単位で平滑**（τ=15 ms）。
- **Type 切替はいったん Amount を 0 へ落としてから差し替える**（τ=8 ms）。
  旧実装は瞬時切替で必ずプツッと鳴っていた。差し替え時に新しい FX の状態も初期化する。
- **連続パラメータ（DECAY / SIZE / ROOT など）をブロック単位で平滑**（τ=30 ms）。
  バッファ 1024 サンプルなら 21 ms の段差が消える。
